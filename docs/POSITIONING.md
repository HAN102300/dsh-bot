## 一、三个必须先纠正的事实

在动手之前，我把此前的资料重新核了一遍，有三处需要修正——它们直接决定立意是否站得住。

### 事实 1：DSH 官方已内置 DeepSeek 适配器 ⚠️

我解包了本机的 `app.asar`（174 MB，306 个 `@deepseek-ai` 包），确认存在：

| 包 | 作用 |
|---|---|
| `dsh-llm-deepseek` | 官方 DeepSeek 适配器（103 KB，走 `/anthropic` Messages API） |
| `dsh-llm-deepseek-account` | OAuth 账号认证 |
| `dsh-llm-deepseek-api-key` | API Key 认证 |
| `dsh-llm-pi-ai` | 另一家适配器（参考实现） |

**含义**：「让 Bot 用上 DeepSeek」这个立意**不成立**——官方已经做了，而且做得比我们原计划更好（`replayState` 原生回传 thinking 块）。

> 详细证据见 [VERIFY-B.md](./VERIFY-B.md)

### 事实 2：Codex 那个 bot 叫 **Dots**，不是 Codex Bot

- **发布时间**：2026-09-29，OpenAI DevDay 2026
- **驱动模型**：GPT-6 Astra
- **定位**：常驻智能体，每个 Dot 有独立云电脑 + 浏览器
- **载体**：ChatGPT 内，不是 Codex 里（Codex 任务是它可以转派的子能力）
- **门槛**：Pro 100/200/500、Business Premium、Enterprise（**$200/月起**）

**含义**：这是继 Grok Bot 之后第二家做「常驻 AI 同事」的，且思路不同。我们必须理解差异，而不是简单对标。

### 事实 3：Grok Bot 与 Dots 是两种不同的产品哲学

| 维度 | **Grok Bot**（xAI, 2026-08-11） | **Dots**（OpenAI, 2026-09-29） |
|---|---|---|
| **核心隐喻** | 一台云电脑，上面住着几个同事 | 一个守着某个目标的同事 |
| **工作中心** | **对话** | **责任** |
| **触发方式** | 你派活 / Routine 定时 | 它自己判断何时继续、何时找你 |
| **招牌能力** | 演示教学（走一遍就学会） | 主动追踪 + 跨渠道（ChatGPT/Slack/Teams/语音） |
| **入口** | 桌面 App + 移动端 | 桌面 + Slack + Teams + 电话 |
| **价格起点** | $40/月（Cursor Teams Standard） | $200/月（Pro） |
| **强项场景** | 办公流程自动化（登录 SaaS 干活） | 长期目标的持续跟进 |

**关键洞察**：Grok Bot 是「**你让它干活**」，Dots 是「**它替你守着**」。

## 二、两家的共同痛点（这是我们的机会）

我把双方官方文档和自己承认的缺陷列出来——**有意思的是，它们承认的问题高度重合**。

| 痛点 | Grok Bot | Dots | 严重度 |
|---|---|---|---|
| **无 dry-run，一跑就是真执行** | eesel 评测："A test run performs real work. If you rehearse an email send, you sent an email." | — | 🔴 极高 |
| **停止不撤销已完成的动作** | — | 官方明确："停止任务不会撤销已经完成的操作" | 🔴 极高 |
| **审计能力缺失** | 只保留最近 **20 条**运行记录 | 未见全量审计 | 🔴 高 |
| **无消费上限** | Continuum："no product-specific spend cap" | 首月额度后按 work/Codex 规则计 | 🟠 中高 |
| **记忆越长，错误延续越久** | — | 卡码笔记："一个持续工作几周的 Agent 如果把错误偏好写进自己的工作笔记，后面的决策可能一直在错误轨道上" | 🟠 中高 |
| **不能选模型 / 成本不可控** | 自动路由，无 picker | 固定 Astra | 🟠 中 |
| **无安全隔离** | 官方："without getting separate security boundaries"，一台机器上的登录态对所有 Bot 可见 | 本地电脑访问默认关闭（做得较好） | 🟠 中 |
| **跨渠道信息串线** | — | 官方承认会检查授权，但"不能只靠一句系统会检查" | 🟡 中 |
| **门槛高** | 必须绑 Cursor 账号 | $200/月 | 🟡 中 |

### 结论：这个品类最大的未解决问题是「**不可逆**」

两家都在文档里承认了同一件事：

> Agent 一旦动手，就收不回来了。

- Grok Bot：测试即生产
- Dots：停止≠撤销

**这是整个品类的结构性缺陷，也是我们唯一能建立真正护城河的地方。**

## 三、融合后的立意

### 3.1 一句话

> **一个会自己盯着事、并且每一次动作都能回滚的本地 AI 同事。**

### 3.2 三个支柱

```
┌─────────────────────────────────────────────────────────┐
│                  一个「可托付」的 Bot                     │
├──────────────┬──────────────┬───────────────────────────┤
│  ① 记得住     │  ② 守得住     │  ③ 收得回                  │
│  （学 Grok）  │  （学 Dots）  │  （我们的原创）             │
├──────────────┼──────────────┼───────────────────────────┤
│ 具名身份      │ 目标驱动      │ 默认 dry-run              │
│ 分层记忆      │ 主动判断继续   │ 副作用分级                 │
│ 持久工作区    │ 异常才打扰     │ 全量审计日志               │
│ 演示教学流程  │ 跨触发源      │ workspace 快照可回滚        │
└──────────────┴──────────────┴───────────────────────────┘
```

**① 记得住**（Grok Bot 的强项，我们照学）
- Bot 有名字、有职责、有工作区
- 记忆跨会话累积，且**分层**（工作/情景/语义）
- 比 Grok Bot 多做一件事：记忆可检索、可蒸馏、可审计

**② 守得住**（Dots 的强项，我们补齐）
- 不只是"定时跑一个流程"，而是"守住一个目标"
- Bot 每轮结束要自问三件事：
  1. 目标达成了吗？
  2. 有新情况需要处理吗？
  3. 需要人拍板吗？
- 只有第 3 项为真时才打扰人

**③ 收得回**（两家都没有，我们的核心差异）
- `dryRun` **默认 true**
- 每个工具有 `sideEffect` 分级：`none` / `local` / `external`
- 外部副作用在 dry-run 下一律拦截，返回"将会做什么"
- 每次运行写全量 JSONL 审计（**不设 20 条上限**）
- workspace 每轮快照，支持 `bot_rollback(runId)`

### 3.3 为什么「收得回」是真护城河

对比一下三家的应对：

| | Grok Bot | Dots | **我们** |
|---|---|---|---|
| 首次执行 | 直接真跑 | 直接真跑 | **先 dry-run** |
| 出错后 | 靠人盯 | 停止但不撤销 | **可回滚到快照** |
| 事后追溯 | 20 条记录 | 无明确 | **全量可导出** |
| 花钱 | 无上限 | 额度制 | **人民币预算熔断** |

**这不是功能差异，是信任模型的差异。**

一个人敢把「每天给我发日报」交给 Bot，和敢把「每周清理一次旧文件」交给 Bot，门槛完全不同。后者一旦做错就是数据丢失。**只有做到可回滚，用户才敢逐步放开权限。**

而权限放开，正是这个品类从"玩具"变成"同事"的唯一路径。

## 四、明确不做什么（保持克制）

| 不做 | 理由 |
|---|---|
| ❌ 不做共享云电脑 | Grok Bot 最大争议点。我们本地优先 |
| ❌ 不做 Computer Use（v1.0） | 投入产出比最低，Playwright 已覆盖部分 |
| ❌ 不做云端托管 | 数据不出本机，这正是国产化合规优势 |
| ❌ 不自研 DeepSeek 适配器 | 官方已有且更好，重复造轮子是浪费 |
| ❌ 不做通用聊天前端 | DSH 已有 Web UI |
| ❌ 不做跨渠道消息（v1.0） | Dots 的 Slack/Teams/电话集成不在首版范围 |

## 五、定位修正后的价值主张

### 5.1 原来的说法（❌ 不成立）

> "把 DeepSeek 接进 DSH，做一个国产 Grok Bot"

**问题**：前半句官方已做，后半句只是模仿。

### 5.2 修正后的说法（✅ 成立）

> **"DSH 上的可托付 Bot 层——让 AI 同事从'敢试'到'敢交'。"**

具体拆成四件官方没做的事：

| # | 我们做的事 | 为什么官方不做 |
|---|---|---|
| 1 | **可回滚执行**（dry-run + 快照 + 全量审计） | 这是产品取舍，不是框架能力 |
| 2 | **目标驱动的主动追踪** | agent-loop 只管单轮，不管跨轮目标 |
| 3 | **中文场景的记忆策略** | 官方适配器只管协议，不管记忆质量 |
| 4 | **人民币预算与峰谷调度** | 官方不关心成本优化 |

### 5.3 一句话电梯陈述

> 现在有两个 AI 同事产品，一个能干活，一个能守事，但**都不敢让你放心把重要的事交出去**——因为它们动手就收不回。我们做的是第三个：**能记住、能守事、还能撤回的本地 AI 同事**，跑在你自己的机器上，用 DeepSeek，花人民币。
